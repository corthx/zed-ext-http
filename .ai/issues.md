# Issue workflow rules

## Starting work on an issue

Always assign the issue to yourself (or to the agent's operator) the moment work begins on it. An issue that is being
worked on must never remain unassigned — assignment is what signals ownership and prevents duplicate effort.

This applies whether the work is opened directly from the issue, started from a branch, or initiated via a merge
request.

## Labels

Always add at least one label when creating an issue. Labels are required to categorize and filter issues effectively.

Use the `enhancement` label only for user-facing changes — changes that affect how people install, configure, or use
the extension. If a change doesn't affect the extension user (e.g. internal refactoring, tooling, CI/CD,
infrastructure), use the `internal` label instead.
